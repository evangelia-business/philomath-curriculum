## What you'll learn

- Why cleanup functions exist and when React calls them
- How to prevent memory leaks from subscriptions and timers
- How to handle stale closures in async effects

## The cleanup function

Every `useEffect` can return a cleanup function. React calls it before re-running the effect and when the component unmounts.

```tsx
useEffect(() => {
  const handler = () => console.log('resized');
  window.addEventListener('resize', handler);

  return () => {
    window.removeEventListener('resize', handler); // cleanup
  };
}, []);
```

Without cleanup, every re-render would add another event listener — and they'd keep firing even after the component is gone.

## Timers and intervals

Always clear timers in the cleanup function.

```tsx
useEffect(() => {
  const id = setInterval(() => {
    setTick(t => t + 1);
  }, 1000);

  return () => clearInterval(id);
}, []);
```

## Handling stale async operations

When an async operation completes after the component unmounts, setting state causes a warning. Use an `isMounted` flag or `AbortController` to cancel it.

```tsx
useEffect(() => {
  let cancelled = false;

  fetchUser(userId).then(data => {
    if (!cancelled) setUser(data);
  });

  return () => {
    cancelled = true;
  };
}, [userId]);
```

With `fetch`, prefer `AbortController`:

```tsx
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/users/${userId}`, { signal: controller.signal })
    .then(res => res.json())
    .then(setUser)
    .catch(() => {}); // AbortError is expected — swallow it

  return () => controller.abort();
}, [userId]);
```

## Key takeaways

- Always clean up subscriptions, timers, and async operations
- The cleanup function runs before the next effect and on unmount
- Use `AbortController` for fetch requests that may outlive the component
