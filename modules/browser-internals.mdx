## What you'll learn

- How browsers parse HTML into the DOM
- The critical rendering path
- How JavaScript execution affects rendering

## The critical rendering path

When the browser receives an HTML document, it follows this sequence:

1. **Parse HTML** → builds the DOM tree
2. **Parse CSS** → builds the CSSOM tree
3. **Combine DOM + CSSOM** → builds the Render tree
4. **Layout** → calculates positions and sizes
5. **Paint** → fills in pixels
6. **Composite** → combines layers onto the screen

## Parsing HTML

The parser reads HTML top-to-bottom. When it encounters a `<script>` tag without `async` or `defer`, it stops, downloads, and executes the script before continuing. This is called render-blocking.

```html
<!-- ❌ Render-blocking — pauses HTML parsing -->
<script src="bundle.js"></script>

<!-- ✅ Deferred — runs after HTML is parsed -->
<script src="bundle.js" defer></script>

<!-- ✅ Async — runs as soon as downloaded, doesn't block -->
<script src="analytics.js" async></script>
```

## DOM vs CSSOM

The DOM represents structure. The CSSOM represents styles. The browser must have both to start rendering. External stylesheets in `<head>` block rendering until they download — another reason to keep CSS small and critical.

## Reflow and repaint

- **Reflow (layout):** triggered when you change geometry — width, height, position, font size. Expensive.
- **Repaint:** triggered when you change appearance only — color, background. Cheaper.
- **Composite only:** triggered by transforms and opacity. Cheapest — runs on the GPU.

```js
// ❌ Forces reflow — reads then writes layout repeatedly
for (const el of elements) {
  el.style.width = el.offsetWidth + 10 + 'px'; // read then write = reflow per loop
}

// ✅ Batch reads, then batch writes
const widths = elements.map(el => el.offsetWidth);
elements.forEach((el, i) => { el.style.width = widths[i] + 10 + 'px'; });
```

## Key takeaways

- The critical rendering path: Parse → Style → Layout → Paint → Composite
- Render-blocking scripts delay the first paint — use `defer` or `async`
- Prefer CSS transforms for animation; they composite without triggering layout
